# Do It All Claude Code

[English](README.md) · [한국어](README.ko.md) · [日本語](README.ja.md) · [简体中文](README.zh-CN.md)

Claude Code を Opus や Sonnet で動かすと、メインセッションがほとんどの作業を自分でこなします。ずっと
安いモデルでも問題なく直せるような修正まで全部です。このプロジェクトは、それを変えるための Claude Code
プラグインと小さなローカルデーモンです。リクエストごとに、メインセッションがそのまま処理するか、安い
モデルで動くサブエージェント数体に作業を渡してメインセッションは計画と確認に回るかを決めます。

最後に確かめたときは、Sonnet のメインセッションでルーターを配布状態のまま有効にしておくと、通過した
タスク 1 件あたりのコストが、素の Claude Code より 33% 少なくなり、通過したタスクも同じでした。多くは
メインセッションが Haiku のコーダー 1 体に修正を渡す形でした。その代わり遅くなります。渡すたびにワーカー
を新しく起動する必要があり、大きいタスクではチームのほうがメインセッション 1 つより目に見えて時間が
かかりました。数値と測り方は [docs/measurements](docs/measurements/) にあります。

CLI とパッケージの名前は `do-it-all-claude-code` です。

## 仕組み

プラグインは Claude Code のフックイベントを `127.0.0.1` のデーモンへ転送します。プロンプトを送ると、
デーモンはモデルを呼ばずにルールだけでリクエストの大きさを見積もり、メインセッション（ここでは「リード」
と呼びます）に、自分で処理するかチームに任せるかを伝えます。

タイポや 1 行の修正のような小さなものはリードがそのままやります。それより大きいものは、リードが Opus 級か
Sonnet のとき、あるいはどのモデルか判別できないときに、チームへ任せます。リードが Haiku のときは L1 程度
は自分でやります。どうせワーカーも同じモデルで動くので、渡しても得がないからです。ルールでは大きさを
判断しづらいリクエストは小さなチームに回し、どの役割が実際に要るかはリードが選びます（Haiku のリードには
短い判断基準が渡され、自分で決めます）。

ワーカーは、たいてい通る一番安い段から始まり（コーダーなら Haiku、effort low）、失敗すると上がります。
2 回続けて外す、レビュアーかテスターに 2 回却下される、あるいはリードが要求する、のいずれかで 1 段上げ
ます。逆にレビュアーから「余裕あり」の判定が続くと 1 段下がります。3 回上げても駄目ならユーザーに尋ねます。

ワーカーが終わると、デーモンはその作業ツリーでプロジェクトのビルド・型チェック・lint・テストを回し、
ワーカーが渡された範囲のファイルだけを触ったかを確認します。何を計画し、実際にどうなり、いくらかかったか
は、すべてローカルの SQLite ファイル 1 つに残ります。

デーモンが動いていなければ、Claude Code はプラグインが無いときと同じように振る舞います。例外はルーターの
ワーカーで、デーモンが動いているときしか書き込めないので、担当範囲の外を触ってしまうことはありません。

## はじめに

Node 24.5 以上、Claude Code 2.1.325 以降が必要で、Windows なら Git Bash も要ります（Claude Code 自体が
必要とします）。

Windows では Claude Code を **Windows Terminal** で実行してください。既定のコンソール ウィンドウはチーム
オフィスの文字を描けず、リストのように見えます。既定にする: Windows Terminal → 設定 → スタートアップ →
既定のターミナル アプリケーション → Windows ターミナル（または Windows の設定 → システム → 詳細設定（以前のバージョンでは開発者向け）→
ターミナル）。そうすれば PowerShell を開いても Windows Terminal の中で開きます。

入り方は 2 通りです。

**ワンコマンド（npm）。** プラグインとステータスラインを入れ、デーモンを起動し、既定で Claude サブスクリプ
ションでルーティングします：

```
npx do-it-all-claude-code setup
```

（または `npm i -g do-it-all-claude-code` のあと `do-it-all-claude-code setup`。）その後 `claude` を実行して
ください。`/office demo` でチームオフィスを下見できます。

**Claude Code の中で。** セッションから始めたい場合：

```
/plugin marketplace add ggreing/do-it-all-claude-code
/plugin install do-it-all-claude-code@do-it-all
/do-it-all-setup
```

最初の 2 行がプラグインを入れ、`/do-it-all-setup` がエンジンをルーターホームに入れてデーモンを起動します。

デーモンは Claude Code のセッション開始時に自分で起動します（`do-it-all-claude-code config set autoStart off`
で止めます）。うまくいかないときは `do-it-all-claude-code doctor` で点検してください。ソースから（貢献者）：
クローンして `npm ci`、そのあと `node packages/cli/src/index.ts setup`。

よく使うコマンドはこのあたりです。

| コマンド | 何をするか |
|---|---|
| `status`, `stop` | デーモンの状態を見る、止める |
| `mode subscription\|api\|direct\|proxy` | モードを切り替える（下記） |
| `policy show\|accept` | プロジェクトの `.do-it-all-claude-code/policy.json` を確認してから適用する |
| `data export`, `data purge` | ルーターが記録した内容を書き出す、消す |
| `uninstall` | `init` がしたことを元に戻す（データフォルダは残る） |

## サブスクリプションか API キーか

既定ではあなたの Claude サブスクリプションで動きます。このモードにはプロキシが無く、ルーターはサブスク
リプションの資格情報を読むことも保存することもありません。Claude Code はこれまでどおり Anthropic と直接
やり取りします。

API キーで使うには `do-it-all-claude-code init --mode api` を実行します。API の手前に小さなローカルプロキシが
入り、呼び出しごとに実際のトークンコストを記録し、1 日の予算を適用します。既定ではローカルトークンごとに
1 日 $100、合計で 1 日 $300 です。各リクエストは最悪のケース（プロンプトの大きさと `max_tokens` をその
モデルの最高レートで見積もった値）をこの上限に対して確保し、リクエストが終わるまで保持します。その分が
収まらなければリクエストを始めません。とはいえこの確保が覆うのはリクエスト本文だけです。API が自分で取り
込むもの（ID で参照したファイル、URL で参照した画像、ウェブ検索などのサーバーツール）は本文に無く、呼び
出しが精算されるときに課金されるので、1 日が上限を少し超えて終わることがあります。キー自体は OS の
キーチェーンにだけ置きます。プロキシが邪魔なときは
`do-it-all-claude-code mode direct` で迂回し、`do-it-all-claude-code mode proxy` で戻せます。

**ローカル TLS。** API キーモードでは Claude Code は `https://127.0.0.1:<port>` でプロキシに接続し、この
ルーターだけが持つ証明書を使います。`openssl` で作り、`127.0.0.1` と `localhost` にのみ有効で、ほかのサイト
の保証はできず、ルーターホームにあなただけが読める形で置きます。Claude Code は設定の `NODE_EXTRA_CA_CERTS`
を通じてこの証明書を信頼します。証明書は期限が切れる前に更新され、更新中に開いていた Claude Code のセッション
は再起動が必要です。`doctor` がそのタイミングを伝えます。別のプログラムがプロキシの停止中にそのポートを奪っても
TLS ハンドシェイクを完了できないので、ローカルトークンもプロンプトもそこには届きません。すでに
`NODE_EXTRA_CA_CERTS` を自分で設定している場合（たとえば社内 CA）、ルーターはあなたの証明書と自分の証明書を
束ねたバンドルを Claude Code の設定に書き込み、社内 CA も信頼されたままにします。`mode direct`・
`mode subscription`・`uninstall` はあなたの元の値に戻し、`doctor` はシェル変数もそのバンドルを指すよう勧め
ます。`openssl` が無ければプロキシは同じリクエスト点検を保ったまま平文 HTTP で動き、`doctor` がそれを伝え
ます。

**社内プロキシの背後で。** プロキシは環境が指定するプロキシ経由で API に届きます。`https_proxy`、
`HTTPS_PROXY`、`http_proxy`、`HTTP_PROXY` のうち最初に設定されたもの（Claude Code が使う順）を用い、
`NO_PROXY` を尊重します。Node 組み込みのプロキシ対応（Node 24.5 以降）を使うので、HTTPS は CONNECT
トンネルを通り、API の証明書は端から端まで検証されます。プロキシ URL に含まれる資格情報はプロキシにしか
渡らず、ログ・エラー・`doctor` には現れません。TLS を覗くプロキシの場合、そのルート証明書を Node が信頼
する必要があり、たとえば `NODE_EXTRA_CA_CERTS` で指定します。SOCKS には対応せず、ルーターが使えない
プロキシ設定なら、こっそり迂回する代わりに起動を止めます。

逆方向では、そのままだと Claude Code が `127.0.0.1:<port>` のローカルプロキシ宛てに送る自分のリクエスト
（ローカルトークンを含む）も社内プロキシを経由してしまいます。そこでプロキシが設定されていると、
`do-it-all-claude-code init --mode api` と `mode api` が Claude Code の設定の `NO_PROXY` に `127.0.0.1` と
`localhost` を追加し（既存の項目は残します）、`mode direct`・`mode subscription`・`uninstall` は自分が
追加した分だけを取り除きます。`do-it-all-claude-code doctor` は両方向を確認します。

## ワーカーと権限

ルーターのワーカーは Claude Code の通常のツールを、ガードを挟んで使います。ガードは担当範囲の外への
書き込み、資格情報ファイルやルーター自身のフォルダに触れること、小さな許可リストの外のコマンドを拒否
します。ただし Bash をあなたの代わりに許可することはしません。ワーカーの `npm test` も、普段の Claude
Code の権限ルールを通ります。ワーカーが毎回聞かれずにビルドとテストを回せるようにするには、こう許可して
おきます。

```
claude --allowedTools "Bash(npm test)" "Bash(npm run *)"
```

何がなぜ拒否されるか、その全一覧は [docs/worker-permissions.md](docs/worker-permissions.md) にあります（英語）。

## データ

記録はすべて自分のマシンの SQLite ファイル 1 つに残り、ルーターが自分から外部へ通信することは、任意の
アップデート確認（下の「アップデート」参照）を除いてありません。
既定ではプロンプトやワーカーの報告内容は残さず、ID・サイズ・結果・コストだけを残します。あとで分析する
ためにプロンプトを残したいときは `recordPrompts` を on にします。また off にすると、次にデーモンが起動
したときに保存したプロンプトを消します。イベントの記録は 30 日間保ちます。

## アップデート

ルーターは新しいバージョンが出たときに知らせることができます。on にしたときだけ動きます。
`do-it-all-claude-code init` が尋ね（Enter で yes）、あとで `do-it-all-claude-code update on` で on、`off`
で off、`check` は設定に関わらず今すぐ確認して現在のバージョンと最新リリースを表示します。既存のインストール
は on にするまで off のままで、その間は `doctor` が on を勧めます。on のとき、デーモンは 1 日に最大 1 回
GitHub の公開リリース一覧を確認します。GitHub には自分のマシンからの通常の Web リクエスト（IP アドレスと
一般的なクライアント名）だけが見え、ほかには何も送られません。プロンプトも、使用状況も、識別情報もありま
せん。新しいバージョンがあれば、ステータスライン（` | update 0.4.0`）とセッション開始時の 1 行の案内に、
自分にだけ、バージョンごとに 1 日 1 回まで表示されます。自動更新はしません。

## チームオフィス

Claude Code で `/office` と入力すると、チャットの横にチームの作業の様子を表示するパネルが開きます。ターミナル
の幅が広ければ、リクエストの最初のワーカーが始まるときに自動で開くこともあります
（`config set officeAutoOpen off` で止められます）。パネルに文字の入力欄はありません。パネルで変えられる設定は Enter で値を切り替え、確認
してから書き込みます。文字の入力が必要な値は、それを変える CLI コマンドと一緒に表示します。

| タブ | 最初の行が答えること | その下 |
|---|---|---|
| オフィス | チームに誰がいて、それぞれ何をしているか | 机についたメンバーごとのモデルと努力レベル、選んだメンバーのセッション（Claude Code 自身の描き方のまま） |
| 作業 | いま何が動いていて、今日はどうだったか | 最近のリクエスト、実行中のものが先頭。ひとつ開くとタイムライン（計画、ワーカー、検証、レビュー）、変更したファイルと `+`/`-` の行数、テスト、ステップの変更、時間とコスト |
| 節約 | 実際に使ったコスト（測定値）と、5 時間・7 日の上限の使用率 | 時間ごと・日ごとのコストの棒グラフ。その下に、推定値と明記して分けた二つの比較があります。ひとつはワーカーのトークンをリードのモデルの価格で数えた場合（前提つき）、もうひとつは実際のリクエストによるホールドアウト比較（サンプル数つき）です。リクエストが足りない比較は、あと何件必要かだけを示し、差は表示しません |
| チーム | プロファイルと、各役割の成績 | 役割ごとの合格率の棒、平均コストと時間、ステップの変更、レベルごとのモデルと努力レベルとその出どころ。最近のステップの変更。いちばん下にトリアージの的中率 |
| 設定 | プロファイルと、自分で決めた設定の数 | パネルで変えられる設定ごとの、実際に効いている値と出どころ（既定値、プロファイル、自分の設定、プロジェクト）。問題は 1 行にひとつずつ。検証コマンド、役割ファイル、`teams.yaml` は、それを編集するコマンドと一緒に |

パネルをクリックするか、ctrl+x に続けて tab を押すとキーボードがパネルに移り、Esc でプロンプトに戻ります。
`o`、`w`、`s`、`t`、`c` でタブを切り替え、↑/↓ と Tab でボタンの間を移動し、Enter で押します。オフィスでは 1〜9
でメンバーを選び、←/→ で強調を移し、`v` でそのメンバーの記録をメイン画面に表示します。作業では Enter で
リクエストを開き、`b` で戻ります。節約とチームでは `p` で期間を 24 時間、7 日、30 日の順に切り替えます。設定
では Enter でいまの行の値を切り替え、変えた値は「前 → 後」と表示されて保留になります。`a` で書き込む前に確認
し（`y` で書き込み、`n` で見送り）、`x` で保留中の変更を捨てます。次の起動や次のセッションから効く値は、その
ように表示されます。

`/office demo` は架空のメンバーでプレビューを表示し、`/office clear` はパネルを空にします。パネルにプロンプト
の内容は表示されません。デーモンが動いていないときは各タブがそのことを 1 行で知らせ、オフィスは Claude Code
自身のイベントからチームを表示し続けます。ルーターの数値だけが欠けます。Windows の従来のコンソールでは、
オフィスはリストになり、そのコンソールが 1 セルで描く記号だけを使います。

パネルの動きがおかしいとき:

- **ウィンドウを狭めたあと、押したキーがプロンプトに入る。** ターミナルがチャットの横にパネルを置くには狭すぎる
  と（110 桁未満）、Claude Code はパネルをプロンプトの上へ移し、キーボードをプロンプトに戻します。ctrl+x に続け
  て tab を押すと、またパネルに移ります。
- **プロンプトの上のパネルが数行しかない。** Claude Code は、最後に決めたプラグインパネルの高さをすべての
  プラグインのパネルに使い、パネルが求める高さよりそちらを優先します。ctrl+x に続けて tab を押してから、
  ctrl+x ↑ で高くしてください。
- **キャラクターの代わりにリストが表示される。** 既定のコンソールウィンドウ（Windows PowerShell、コマンド
  プロンプト）はキャラクターの記号を 2 セル幅で描くため画面が崩れるので、そこではオフィスをリストで表示します。
  Claude Code を Windows Terminal で開いてください。Windows Terminal を既定のターミナルにする方法は
  [はじめに](#はじめに)の節にあります。

`do-it-all-claude-code config set office off` を実行すると、それ以降に始めるセッションからパネルが無効に
なります。Claude Code 2.1.325 以上が必要です。0.5.0 より前のバージョンにあったブラウザのダッシュボードは
なくなりました。

## 設定とプロファイル

プロファイルは、いくつかの設定をまとめて動かします。3 つあり、選ばなければ `balanced` です。

| | save（節約） | balanced（バランス） | quality（品質） |
|---|---|---|---|
| 委任を始めるレベル | balanced と同じ | リードが Opus か Sonnet なら L1、Haiku なら L2 | L2。L1 はリードが自分でやる |
| L2 のチーム | コーダー 2 人とテスター。レビューはリードが行う | アーキテクト、コーダー 2 人、レビュアー、テスター | 同じチームを 1 段ずつ高く |
| L3 のチーム | コーダーは Sonnet から | コーダーは Opus から | コーダーは Opus。アーキテクトとレビュアーは Opus の最も高い effort |
| 「余裕あり」の判定が続いたとき | ワーカーが 1 段下がる | ワーカーが 1 段下がる | そのまま |
| リクエスト 1 件の予算 | 既定値の 0.6 倍 | 既定値 | 既定値の 1.5 倍 |

測定したのは `balanced` だけです。このページ冒頭の 33% はそのプロファイルの結果です。`save` と `quality`
は同じ設定をどちらかへ動かしたもので、まだ測定していません。コストや合格率がどう変わるかは分かっていません。

変えるには、チームオフィスの設定タブで値に移動し、Enter で選択肢を順に切り替えます。`a` に続けて `y` を
押すと変更が適用され、`x` で取り消します。CLI でもできます。

```
do-it-all-claude-code config set profile quality
```

自分で決めた値はプロファイルより優先されます。予算（`budgetsUsd`）、委任を始めるレベル（`delegateFrom`）、
`stepDown`、`teams.yaml` のチーム構成がそうです。設定タブは値ごとに出どころ（既定値、プロファイル、自分の
設定、プロジェクトのファイル）を表示し、`do-it-all-claude-code config set <key> default` で自分の値を
取り除けます。どちらの方法も同じ検査を通り、同じ履歴（`do-it-all-claude-code config history`）に残ります。

0.5.0 で増えた設定は 2 つです。

| キー | 内容 | 既定値 |
|---|---|---|
| `officeAutoOpen` | リクエストの最初のワーカーが始まるときに、チームオフィスが自動で開く | on |
| `autoStart` | Claude Code のセッションが始まるとき、デーモンが動いていなければ起動する | on |

役割ファイル、`teams.yaml` 全体、プロジェクトの検証コマンドにはエディタが要ります。パネルはそれらを開く
コマンド（`role edit`、`preset edit`）と一緒に表示するだけです。

## 委任が今も得かを確かめる

本来ならチームに回すリクエストの 10 件に 1 件ほどを、わざとリードに直接やらせて、比べる相手を作ります。
既定では比較の結果を見せるだけで、`autoRelease` を on にしない限り、自分から何かを止めることはありません。
比較そのものが要らなければ `holdoutRate` を 0 にしてください。

## まだうまくいかないこと

ワーカーが終わったあとに回す検査は、結局そのプロジェクトのテストです。テストが見ない形で間違っている修正
は通ってしまいます。そのときリードが作業を 1 段上へ戻すことはできますが、まず気づく必要があります。

節約タブの比較の「受容」は、続く数個のプロンプトの間に変更を取り消したり、同じ依頼をやり直したり、苦情を
言ったりしなかった、という意味です。作業が実際に良かったかを測った値ではなく、良かったかもしれない割合の
上限です。

自動の切り替えは、委任が明らかに割高になった場合を捕まえるためのもので、細かく調整するものではありません。
扱う標本の大きさでは、25% ほどの損失を偶然と区別できません。

まだ正式リリース前なので、コマンドや既定値は変わることがあります。
